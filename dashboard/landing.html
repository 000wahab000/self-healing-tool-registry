Why it's needed

Real APIs drift. Agents are frozen.

A tool schema is a snapshot. The API behind it keeps moving, and the agent only finds out when a call fails.

Why it's better

Heal the tool, not the prompt.

Frameworks retry the same call and hope. The registry treats drift as a tool problem and fixes it once, at the wire, so the agent and its prompt stay exactly as shipped.

Detection & classification

From a failed call to a diagnosis.

A call has failed on a 4xx (400, 401, 404, 422), or on a 200 whose body fails the tool's output postcheck. The registry then fetches the live OpenAPI spec and diffs it against the v1 snapshot to name the drift.

If the spec has not changed, it is not drift: the error goes back to the agent untouched.

Pipeline

  1. 01CallForward the agent's v1 args, unchanged.
  2. 02Detect4xx, or a 200 that fails the postcheck.
  3. 03DiagnoseDiff the live spec against v1.
  4. 04ClassifyOne drift class, or none.

Drift classes

SCHEMA driftRequest or response shape changed. Healable.
AUTH / header driftA header is now required.
ROUTE driftThe path moved.
BUSINESS errorSpec unchanged: handed back to the agent untouched.
The patch

A small, typed fix. Never a guess.

The registry never edits the prompt. It rewrites the call: the agent sends the v1 shape, the live API receives what it wants.

Agent sends · v1
POST /users/lookup
{ "user_id": "123" }
→
Live API wants · v2
POST /users/lookup
X-Tenant-Id: <TENANT_ID>
{ "target": { "id": 123 } }
Fix · 3 ops move user_id → target.id cast string → int header X-Tenant-Id ← config TENANT_ID

Preverify, replay, commit

Check against the API's read-only validate endpoint, replay once, then commit in memory: version +1, wire_schema updated, agent_schema unchanged.

preverify ✓replay ×1 ✓commit v+1

Stored by fingerprint

The fix is stored under the drift's fingerprint, so the next identical drift heals at tier 0, with no spec diff.

fingerprint→stored fix→tier 0

Values are never invented

Values only come from the agent's input or config. The 4-op DSL (move, cast, header, route) cannot write a literal.

It refuses instead of guessing.

The live spec adds a required priority, and nothing in the agent's input or config can supply it. The registry refuses. The agent skips that tool and finishes the rest of the task.
